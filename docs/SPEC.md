## 1. コンセプト

スマホ画面の中に小さな部屋があり、ペットがそこで**勝手に生活している**。

- ユーザーが見ていない間も、ペットは寝る・食べる・遊ぶ・散らかす・趣味を見つける・拾ってくる・独り言を言う。
- 開いたときに「留守中の日記（タイムライン）」が残っていて、**閉じている間も生きていた**ことが分かる。
- **世話不足では死なない**。世話をしないと「弱る」のではなく、**勝手に変な方向へ成長する**。
  - 例: ごはんをあげないと、自分で冷蔵庫を開けるようになり「自立的・食いしん坊」に育つ。
  - 例: 掃除しないと、散らかった部屋に適応して「ずぼら・収集癖」に育つ。
- ただし**寿命はある**。一生を終えると次の世代のたまごが残り、性格や思い出の一部が引き継がれる（→ 7 章）。
- 世話は「義務」ではなく「育ち方への介入」。放置も一つの育て方。

### デザイン原則

| 原則 | 意味 |
|---|---|
| 罰より変化 | 放置のペナルティは死や病気ではなく、性格・見た目・趣味の変化 |
| 死は寿命だけ | 死はユーザーの失敗の結果ではなく、一生の終わりとして必ず訪れる |
| 眺めて楽しい | 操作しなくても、部屋を見ているだけで何か起きている |
| 数秒で満足 | 1 回の起動は 30 秒〜2 分で完結できる。ミニゲームも数秒 |
| 日記が主役 | 起動時の一番のご褒美は「留守中に何があったか」を読むこと |

## 2. 前提・非機能要件

| 項目 | 内容 |
|---|---|
| 形態 | Web アプリ（SPA）＋ 小さなバックエンドサーバー。個人用 |
| 実行環境 | 常時起動の **Windows ミニ PC** でサーバーを動かし、同じ LAN 内のスマホ / PC のブラウザからアクセス |
| 認証 | なし（ログイン・アカウント不要）。LAN 内利用が前提 |
| データ保存 | **サーバー側**の SQLite ファイル（スマホと PC で同じペットを共有） |
| 対象画面 | スマホ縦画面に最適化（基準 390×844） |
| PC 表示 | 画面中央にスマホ型のフレーム（最大幅 430px 程度）を表示し、スマホライクに操作できる |
| 外部通信 | 外部 API は使わない。インターネット接続なしで動作 |
| 時間 | サーバーの時刻を正とする（端末ごとの時計のずれの影響を受けない） |
| タイムゾーン | 設定で指定（初期値: Asia/Tokyo）。就寝時刻・日付区切りに使う |

> ⚠️ 認証がないため、**インターネットには公開しない**（ルーターのポート開放をしない）。
> 必要になったら、環境変数で設定する簡易アクセスキー（URL パラメータまたは Cookie）を後から追加できるようにしておく。

## 3. システム構成

### 3.1 全体像

```
 ┌── スマホ ブラウザ ──┐   ┌── PC ブラウザ ──┐
 │  Web クライアント     │   │ Web クライアント   │
 │  (描画・操作・演出)   │   │ (同じもの)         │
 └──────────┬───────────┘   └────────┬───────────┘
            │  HTTP (JSON) / 同じ LAN     │
            └──────────────┬─────────────┘
                 ┌─────────▼──────────┐
                 │   Pocco サーバー    │
                 │  ・REST API         │
                 │  ・シミュレーション │ ← 状態を持つのはここだけ
                 │  ・静的ファイル配信 │
                 └─────────┬──────────┘
                   ┌───────▼────────┐    ┌───────────────┐
                   │ SQLite (pocco.db) │    │ data/photos/  │
                   └────────────────┘    └───────────────┘
```

- **サーバーが唯一の正**（Single Source of Truth）。クライアントは状態を持たず、表示と操作だけを担当する。
- クライアントは「状態をまるごと上書き保存」せず、**操作（コマンド）を送る**。サーバーがそれを適用する。
  → スマホと PC を同時に開いていても、データが食い違わない。

### 3.2 技術スタック（提案）

| 領域 | 採用候補 | 理由 |
|---|---|---|
| 言語 | TypeScript（フロント・サーバー共通） | シミュレーションのコードを共有できる |
| 構成 | npm workspaces のモノレポ | `sim` をサーバーとクライアントで共有 |
| サーバー | Node.js + Hono（tsx で TypeScript をそのまま実行） | 軽量。ビルド済みのフロントも一緒に配信 |
| DB | SQLite（better-sqlite3、SQL を直接書く） | 1 ファイルで完結・バックアップが簡単・同時書き込みでも壊れにくい |
| クライアント | Vite + React + Zustand | — |
| 描画 | Canvas 2D（ドット絵スプライト） | 着せ替えのレイヤー合成・写真保存が容易 |
| テスト | Vitest | シミュレーションの単体テスト |
| 任意 | PWA 化 | スマホのホーム画面から起動（LAN 内 HTTP のため制約あり。3.4 参照） |

**JSON ファイルでなく SQLite を推奨する理由**: タイムラインや写真のメタデータは増え続けるため、全体を毎回 JSON で読み書きするのは非効率。また書き込み途中の停止でファイルが壊れる心配がない。ペット状態のような構造が変わりやすいデータは、SQLite の JSON カラムに入れて柔軟性を保つ。

### 3.3 ディレクトリ構成

```
pocco/
  packages/
    sim/          … シミュレーションエンジン（純粋な TS。UI・DB 非依存）
      engine.ts     時間を進める（state, from, to, seed → state, events）
      needs.ts      欲求の増減
      brain.ts      行動選択
      growth.ts     成長・進化・寿命
      events/       イベント定義（データ）
      rng.ts        シード付き乱数
    data/         … マスタデータ（食べ物・アイテム・家具・着せ替え・種族・会話テンプレ）
  apps/
    server/       … API・DB・シミュレーション実行
    web/          … クライアント（画面・Canvas 描画・ミニゲーム）
  assets/         … ドット絵スプライト、パレット定義
  data/           … 実行時データ（pocco.db, photos/）※ git 管理外
```

### 3.4 サーバー環境（Windows ミニ PC）

| 項目 | 方針 |
|---|---|
| OS | Windows（常時起動） |
| ランタイム | Node.js LTS（Windows 版）。`better-sqlite3` は Windows 用のビルド済みバイナリが使える |
| 起動方法 | `npm run build` → `npm start` で起動。**自動起動（サービス化など）はプロジェクト外で管理する** |
| ポート | 例: `8787`。サーバーは `0.0.0.0` で待ち受け |
| ファイアウォール | Windows Defender ファイアウォールで、このポートの受信を**プライベートネットワークのみ**許可 |
| アクセス方法 | スマホ・PC から `http://<ミニPCのIPアドレス>:8787`。ルーターで IP を固定（DHCP 予約）するか、`http://<PC名>.local` を使う |
| スリープ | **プロジェクト外で管理する**。止まっていた場合もキャッチアップ方式（4.4）で復帰後に追いつく |
| 時刻 | Windows の時刻同期を有効にしておく。タイムゾーンはアプリ設定で指定 |
| データの場所 | 例: `C:\Pocco\data\`（`pocco.db` と `photos\`）。パスは環境変数で変更可能 |
| バックアップ | 1 日 1 回、サーバー自身が `data\backups\` に DB のコピーを作る（直近 14 世代分＝ほぼ 1 世代ぶんを保持） |
| 更新 | git pull → `npm install` → `npm run build` → サーバー再起動 |

- パス区切りや改行コードの違いで動かなくならないよう、コード内のパスは `path.join` で組み立て、開発は Windows でも Mac/Linux でも動くようにする。
- HTTPS は使わない（LAN 内の HTTP）。そのため、PWA のインストールや Service Worker など HTTPS が必要なブラウザ機能は、スマホでは使えない場合がある（→ 拡張で検討）。
  - 画面のコードでは、安全な接続（HTTPS・localhost）でしか使えない API（`crypto.randomUUID`・Web Share API など）に頼らない。操作の ID は `crypto.getRandomValues` で作る（`apps/web/src/id.ts`）。動作確認は localhost だけでなく、LAN の IP アドレスでも開いて行う。

## 4. 時間とシミュレーション（最重要）

### 4.1 「閉じている間も生活している」の実現方法

サーバーは常時動いているが、**リクエストが来たときにまとめて計算する（キャッチアップ方式）**を基本とする。

1. DB に `lastSimulatedAt`（最後にシミュレーションした時刻）を保存する。
2. クライアントから何かリクエストが来たら、まず `lastSimulatedAt` から現在時刻までを **10 分刻みの tick** で進める。
3. 各 tick で「欲求の変化 → 行動の選択 → イベント抽選」を行い、発生したイベントをタイムラインに保存する。
4. そのあとでリクエスト（ごはんをあげる等）を処理する。
5. 加えて、サーバー内で **10 分ごとの定期実行** も行う（誰も開いていなくても日記が進む／計算が一度に溜まりすぎない）。

→ どちらの経路で進めても、同じ関数・同じ乱数なので**結果は同じ**になる。

### 4.2 決定論的な乱数

- 乱数は `seed = hash(petId, tickの時刻)` から生成する。
- 同じ時間帯を何度計算しても同じ結果になる → テスト・不具合の再現がしやすい。

### 4.3 開いている間の見え方

- クライアントは 30〜60 秒ごと、および画面に戻ってきたとき（`visibilitychange`）に状態を取得する。
- tick の間の「うろうろ歩く」「まばたき」などの細かい動きはクライアント側の**演出**（見た目だけ）で、状態は変えない。
- 別の端末で操作した結果も、次の取得で反映される。

### 4.4 長時間放置・異常時の扱い

| 状況 | 扱い |
|---|---|
| サーバーが止まっていた（〜72 時間） | 再起動後の最初のリクエストで 10 分 tick でキャッチアップ |
| サーバーが 72 時間以上止まっていた | 超過分は 1 時間 tick の簡易シミュレーション（重要なイベントだけ記録） |
| サーバー時刻が過去に戻った | シミュレーションしない（`lastSimulatedAt` を更新するだけ） |

### 4.5 1 日のリズム

- 現実の時刻に応じて、朝・昼・夕方・夜で部屋の照明（パレット）が変わる。
- 就寝時刻の初期値は 23:00〜7:00。性格（朝型/夜型）で ±2 時間ずれる。
- 就寝中に開くと寝ている姿が見える。起こすこともできる（機嫌が少し下がる）。

### 4.6 実装メモ（P1）

| 項目 | 実装 |
|---|---|
| tick | 10 分境界（0分・10分・20分…）にそろえる。境界をまたいだ分だけ進むので、定期実行とまとめ計算で結果が一致する |
| 定期実行 | サーバーが 1 分ごとに `advance` を呼ぶ |
| 「見ている」判定 | `GET /api/state`（画面は 30 秒ごとに呼ぶ）で `lastSeenAt` を更新。最後に見てから 30 分以上たつと「留守」扱い |
| 留守の期間 | 30 分以上あけて開いたとき、その期間を記録して留守中サマリーに使う。「○時間ぶり」を出すのは戻ってから 30 分のあいだで、その留守の日記をまだ読んでいないときだけ（見続けたり、少し閉じて開き直したり、読んだあとに日記が増えたりしたときに前の長い留守を出さない）。読んでも記録は消さず、読んだ印だけつける（おかえりの挨拶に使うため）。日記画面は開いたときの留守の期間を覚えて見出しに使う |
| 時間のかかる行動 | 睡眠・昼寝（今後: 散歩など）は**始まったときと終わったときの両方**を日記に書く（「ベッドに入った」→「目をさました（8時間眠っていた）」）。終わりの記録は、同じ時刻に起きたほかの出来事より前に並べる |
| 短い行動 | 遊ぶ・窓の外を見る は始まったときに 1 件だけ書く |
| まとめ | 同じ行動が続いたときは、始まり・終わりを 1 回ずつにまとめる |
| 1 日の上限 | 普通の出来事は 1 日 30 件まで（サーバーで間引く） |
| 早送り | `POCCO_DEBUG=1`（`npm run dev` では既定で有効）のとき、設定画面から時間を進められる。ずらした時間はメモリ上だけで、再起動で戻る |

## 5. ビジュアル

### 5.1 方向性

**「ドット絵だけど、モダンな配色」**。たまごっちユニのように、ドットの粗さは残しつつ、白黒液晶ではなく明るく柔らかいフルカラーにする。

| 項目 | 方針 |
|---|---|
| 解像度 | 部屋の内部解像度 **128×128px**（仮）。画面幅に合わせて**整数倍**で拡大（ぼかさない） |
| ペット | 基本 **32×32px**（ベビーは 16×16〜24×24、おとなは最大 40×40） |
| パレット | 全体で 32 色程度の固定パレット。パステル寄りで彩度は中〜高、黒は使わない |
| 輪郭線 | 黒ではなく、塗りの色より一段暗い**色付きの輪郭線** |
| 影 | ベタ塗り 1〜2 段階。グラデーション・ディザは基本使わない |
| アニメーション | 2〜4 コマの簡単なループ（待機・歩き・食べる・寝る・喜ぶ・怒る） |
| 時間帯 | 同じスプライトに**パレットを差し替える**ことで朝・夕方・夜を表現 |
| UI 部品 | ボタン・カード・タブは今どきのフラットデザイン（角丸・柔らかい影）で、ドット絵の部屋との対比を出す |
| フォント | 見出し・吹き出し・日記はドット風の日本語フォント（例: DotGothic16）、細かい説明文は通常のフォント |

### 5.2 実装メモ

- Canvas は `imageSmoothingEnabled = false`、CSS では `image-rendering: pixelated`。
- スプライトは画像ファイルではなく**コードで描く**（D13）。文字 1 つが 1 ドットの配列と、パレットのキーで色を指定する（`apps/web/src/render/`）。
- 拡張しやすいように、**素材は 1 つずつ個別のファイル**にする（`apps/web/src/render/assets/`）。フォルダごとに `import.meta.glob` で自動で読み込み、**ファイル名が ID** になる。足すときはファイルを 1 つ置くだけ（sim 側の一覧にも ID を足す。抜けや打ちまちがいはテストで見つかる）。

| フォルダ | 中身 | 形 |
|---|---|---|
| `pet/` | 体を作る `body.ts`・形の部品 `shapes.ts`・たまご・眼鏡、`features/` に頭の飾り | スプライト |
| `pet/species/` | 種族ごとの見た目（体の形・大きさ・目の位置と大きさ・ふだんの口・ほっぺ）。手描きのスプライトで置きかえることもできる | 設定 |
| `pet/poses/` | 動き。コマごとに目・口・つぶれ具合・上下左右のずれ・足・しるし（ハート・むかっ）を書く | コマの一覧 |
| `wear/hat` `wear/hand` | 帽子・手に持つ物 | スプライト |
| `wear/accessory` | アクセサリ | スプライト＋置く場所 |
| `wear/clothes` | 服 | 塗りかえる行の範囲と色 |
| `furniture/` | 模様替えの家具 | スプライト |
| `food/` `treasure/` | 食べ物・拾い物のアイコン（12px 前後） | スプライト |
| `room/` | 固定の家具（窓・冷蔵庫・ベッド・ラグ）、`wallpaper/` `floor/` に模様 | 描く関数 |
| `litter/` `objects/` `effects/` `minigame/` | 散らかり・書き置き・形見・Zz・きらっ・ミニゲームの小物 | スプライト |

- 描く側（`room.ts`・`pet.ts`）は素材を並べるだけ。スプライトの型と描き方は `render/sprite.ts`。
- 体は種族の形から輪郭・影・ハイライト・顔を自動で作り、段階ごとに大きくなる。形は まんじゅう・おもち・四角・しずく・洋なし の 5 つを組み合わせ、大きさと顔で種族ごとに変える（おとなの 12 種で同じ体は多くても 2 つ）。
- 動きの使い分け: 寝ている → 寝る、歩いている → 歩き、ひとり遊び → 遊ぶ、冷蔵庫で食べている → 食べる、それ以外 → 待機（ときどきまばたき）。大好きな食べ物・気に入った服・ミニゲームの成功・話しかけたとき → 喜ぶ（2.4 秒）、苦手な食べ物・気に入らない服 → 怒る。動きは画面側の演出だけで、状態は変えない。
- 持ち物のアイコン（もちもの・ごはん・図鑑・思い出）はドット絵で、表示する大きさに収まる整数倍で拡大する（`ui/ItemIcon.tsx`・`render/icons.ts`）。食べ物・拾い物は専用の絵、着せ替え・家具は部屋で使う絵をそのまま使い、服だけはアイコン用にシャツ（首まわりの服はマフラー）の形で描く。壁紙・床は色見本。趣味・できごと・操作ボタンは絵文字のまま。
- 自撮りの写真は笑顔のコマで描く。ミニゲームでも、動いているときは歩き、リズムタップの拍では遊ぶのコマを使う。
- 着せ替えは「体 → 服 → アクセサリ → 帽子 → 手持ち」の順にレイヤーを重ねる。各アイテムは成長段階・種族ごとの取り付け位置（アンカー）を持つ。
- 写真は内部解像度の 4〜8 倍で書き出し、ドットのくっきり感を保つ。

## 6. ペットのパラメータ

### 6.1 欲求（Needs）… 0〜100、時間経過で変化

| 欲求 | 増減 | 高いとき（放置時）に起きること |
|---|---|---|
| 空腹 | 時間で増加 | 自分で冷蔵庫を開ける／拾い食い → 自立度↑・好みが偏る |
| 眠気 | 起きていると増加 | その場で寝落ちする（ソファ・床など） |
| 退屈 | 時間で増加 | 一人遊び・散らかす・趣味を探す → 好奇心↑ |
| さびしさ | 最後の操作からの経過で増加 | 独り言・窓の外を見る → 甘えん坊 or 自立へ分岐 |

※ どの欲求も死や病気には繋がらない。**ペットは自分でなんとかしようとし、その結果が性格に反映される。**

### 6.2 部屋の状態

| 項目 | 内容 |
|---|---|
| 散らかり度 0〜100 | 遊ぶ・食べる・拾い物で増える。一定以上でゴミ・おもちゃが部屋に描画される |
| 設置家具 | ペットの行動候補を増やす（本棚 → 読書、植木鉢 → 水やり など） |

### 6.3 性格（Personality）… 各軸 -100〜+100、ゆっくり変化

| 軸 | − 側 | + 側 | 主な変化要因 |
|---|---|---|---|
| 活発さ | のんびり | やんちゃ | 遊ぶ頻度、ミニゲーム |
| きれい好き | ずぼら | 几帳面 | 掃除の頻度、散らかり度の平均 |
| 好奇心 | 慎重 | 冒険好き | 散歩・新しいアイテム・家具 |
| 距離感 | 自立 | 甘えん坊 | 世話の頻度、さびしさの放置 |
| 食欲 | 小食 | 食いしん坊 | ごはんの量、自分で食べた回数 |
| 生活リズム | 朝型 | 夜型 | アプリを開く時間帯、夜に起こした回数 |

- 性格は行動の選ばれやすさ・会話の口調・進化先に影響する。
- 1 日あたりの変化量に上限を設け、急に別人にならないようにする。

### 6.4 好み・趣味

- **食の好み**: 食材タグ（甘い/しょっぱい/辛い/野菜/肉/魚/謎）ごとの好感度。食べた回数と反応で形成。
- **趣味**: 条件を満たすと「趣味を見つけた」イベントで獲得（最大 3 つ）。趣味ごとに専用の行動・日記・拾い物が追加される。

| 趣味例 | 獲得条件の例 | 追加される行動 |
|---|---|---|
| ガーデニング | 植木鉢を置く + きれい好き+ | 水やり、芽が出る |
| 読書 | 本棚を置く + のんびり | 本を読む、本の感想を言う |
| 収集 | 散らかり度が高い期間が長い + 好奇心+ | 拾い物を棚に並べる |
| 音楽 | 楽器を拾う | 夜に鼻歌、演奏 |
| 料理 | 自分で冷蔵庫を開けた回数が多い | 謎の料理を作る |
| 天体観測 | 夜型 + 窓際で過ごす時間が長い | 夜に窓の外を見る |

## 7. 一生と世代交代

### 7.1 ライフステージ

一生は **14 日**（現実時間）。

| 段階 | 年齢の目安（現実時間） | 特徴 |
|---|---|---|
| たまご | 〜1 時間 | 画面タップで少し早く孵る |
| ベビー | 〜1 日 | 性格の変化量が大きい。片言で話す |
| こども | 1〜3 日 | 趣味を見つけ始める |
| ティーン | 3〜6 日 | 性格が固まり始める |
| おとな | 6〜11 日 | 進化先が確定。一番活動的 |
| シニア | 11〜13 日 | 動きがゆっくり・よく寝る・昔を思い出す日記が増える |
| 最期の日 | 13〜14 日 | ほとんど眠っている（7.3） |
| 旅立ち | 14 日 | 一生を終える |

- 各段階の切り替わり時に、**性格ベクトルが最も近い見た目（種族）**に進化する。
- おとなの姿は 12〜16 種類程度を想定。「ちゃんと世話した」系だけでなく、「放置しまくった」系にも魅力的な姿を用意する（例: 冷蔵庫の主、ゴミ山の王、夜更かし詩人）。
- シニアになると見た目にも変化（白い毛・眼鏡・杖など、種族ごとに 1 パターン）。
- 期間はすべて設定ファイルで調整可能にする（開発中はデバッグ早送りで確認）。

### 7.2 寿命

- 基準は **14 日**。世話の内容で**少しだけ**前後する（最大 ±12 時間）。
  - 延びる要因: 規則正しい睡眠、食事の偏りが少ない、よく遊んだ
  - 縮む要因: 夜ふかしが続く、同じものばかり食べる
  - ※ 「放置＝早死に」にはしない。放置しても自分で生活するので、寿命への影響は小さい。
- 寿命の数値や残り日数はユーザーには見せない。シニアになると「そろそろかな」という雰囲気が日記・会話から伝わる。
- 以降の段階の境目（シニア・最期の日）も、寿命の前後に合わせてずらす。

### 7.3 最期の迎え方（しんみり）

**看取れるようにする**。いない間にいつの間にか死んでいた、にはしない。
演出のトーンは**静かでしんみり**。明るい BGM や「おめでとう」的な表現は使わない。

#### 最期の日（寿命の 24 時間前〜）

- ほとんど寝ている。起きている時間は短く、窓の外を見たり、形見になるアイテムのそばにいたりする。
- 部屋のパレットは少しだけ彩度を落とし、夕方のような柔らかい色になる。
- 日記は短く静かな文になる（「ひだまりで ずっと ねていた。」「{keepsake}を ながめていた。」）。
- 話しかけると、昔の出来事を 1 つ思い出して話す（一生の日記から重要度の高いものを選ぶ）。
- ごはんは少しだけ食べる。遊び・散歩はしない。

#### 看取った場合（最期の日にアプリを開いた）

1. ペットがゆっくり目を覚まし、ユーザーの方を向く。
2. **最後のひとこと**（2〜3 行）を 1 行ずつゆっくり表示する。
   - 一生の中で多かった出来事・好きだった食べ物・趣味・ユーザーとの関わりから生成する。
   - 例: 「トマト、いっぱい くれたね」「れいぞうこ、かってに あけて ごめんね」「……ありがとう」
3. 目を閉じ、部屋の照明がゆっくり暗くなる（数秒のフェード）。
4. ペットの姿が小さな光になって窓の外へ消える。
5. 黒い画面に「{name} は {n} 日 生きました」と、生年月日〜旅立ちの日を表示。
6. タップすると空っぽの部屋に戻る。

- 演出中はスキップできないが、途中で閉じても次に開いたときに続きから再生する。
- 最後の場面は自動で写真として保存する（アルバムと思い出に登録）。

#### 看取れなかった場合（最期の日に誰も開かなかった）

- 寿命の時刻に静かに旅立つ。
- 次に開いたとき、空っぽの部屋に**置き手紙**が置かれている。タップすると最後のひとことが手紙として読める。
- 日記の最後のエントリは「{name} は しずかに たびだった。」

#### 旅立ちのあと

- 部屋はしばらく空っぽのまま。家具や散らかりもそのままにしておく（掃除はできる）。
- **次の世代のたまごは、旅立ちの翌朝（6:00）に部屋に現れる**。すぐに次へ進ませず、余韻の時間をとる。
  - 翌朝に開くと、窓際に形見のアイテムとたまごが並んでいる。日記の新しいページが始まる。

### 7.4 次の世代への引き継ぎ

| 引き継ぐもの | 内容 |
|---|---|
| 性格 | 親の性格の 20〜30% をスタート値として受け継ぐ（残りはランダム） |
| 好み | 親が一番好きだった味タグに少しだけ好感度が付いた状態で生まれる |
| 形見 | 親が一番大事にしていたアイテム 1 つが部屋に残る |
| 部屋・持ち物 | 家具・壁紙・持ち物・着せ替えはそのまま残る |
| 図鑑・写真・日記 | すべて残る（世代をまたいで集める） |
| 引き継がない | 趣味（ただし親の趣味は見つけやすくなる）、欲求、進化先 |

### 7.5 思い出（メモリアル）

- 旅立ったペットは「**思い出**」画面に並ぶ（家系図のように世代順）。
- 各ペットのページ: 姿（おとな/シニア）、生きた期間、性格のまとめ、趣味、好きだった食べ物、代表的な日記 5 件、最後のひとこと、写真。
- 過去の世代の日記は、世代ごとに読み返せる。

## 8. 行動 AI（brain）

各 tick でペットの行動を 1 つ選ぶ。**ユーティリティ方式**（候補ごとにスコアを計算し、重み付き抽選）。

```
スコア = 基本値
       × 欲求による補正（空腹が高い → 食べる系↑）
       × 性格による補正（やんちゃ → 遊ぶ系↑）
       × 時間帯による補正（夜 → 寝る↑）
       × 部屋による補正（本棚がある → 読書が候補に入る）
       × ライフステージ補正（シニア → 寝る↑・散歩↓）
```

行動の例: 寝る / 昼寝 / うろうろ / 一人遊び / 冷蔵庫を開ける / 窓の外を見る / 散らかす / 片付ける（几帳面なときだけ）/ 趣味の行動 / 散歩に出る / 独り言

行動が変わったタイミングや、確率で発生する出来事を **イベント** としてタイムラインに記録する。

## 9. タイムライン（日記）… 目玉機能

### 9.1 表示イメージ

```
┌──────────────────────────────────┐
│ 🕒 5時間ぶりだね                    │ ← 留守中サマリー
│ 寝た 2 回・拾い物 1 個              │
│ 新しい趣味: ガーデニング            │
├──────────────────────────────────┤
│ 今日                                │
│ 14:32 ベッドの下からコインを見つけた。 🪙 │
│ 13:10 昼寝をしていた。（〜13:50）         │
│ 12:48 冷蔵庫を勝手に開けた。              │
│ 11:03 植木鉢に水をあげた。 🌱             │
│ 昨日                                │
│ 23:41 窓の外をずっと見ていた。            │
└──────────────────────────────────┘
```

### 9.2 仕様

- 新しい順に表示、日付ごとに区切る。
- 起動時、留守中に新しいエントリがあれば**「留守中サマリー」カード**を最上部に出し、未読エントリを強調表示する。
  - 「未読」はサーバーで管理する（スマホで読んだものは PC でも既読）。
- 連続する同じ行動はまとめる（例: 「13:10〜13:50 昼寝をしていた」）。
- エントリには重要度（普通 / ちょっと珍しい / 大事件）を持たせ、大事件（進化・趣味獲得・レア拾い物・旅立ち）はアイコンと色で目立たせる。
- 1 日に記録する通常エントリは最大 30 件程度に間引く（重要度の低いものから削る）。
- エントリをタップすると、関連するアイテムや写真に飛べる。
- 保存期間: 無期限。世代ごとに区切り、古いものは月ごとに折りたたむ。
- ユーザーの操作（ごはんをあげた等）も薄い色で記録する（「あなたがトマトをくれた」）。

### 9.3 文章テンプレート

イベントはデータとして定義し、テンプレートで文章を生成する。性格によって言い回しを変える。

```ts
{
  id: "fridge_open",
  when: { needs: { hunger: ">= 70" }, userAbsent: true },
  weight: 10,
  cooldownMinutes: 180,
  effects: { hunger: -40, mess: +10, personality: { independence: +2, appetite: +1 } },
  texts: {
    default: ["冷蔵庫を勝手に開けた。", "冷蔵庫の{food}をこっそり食べた。"],
    tidy:    ["冷蔵庫を開けて、ちゃんと閉めた。"],
    messy:   ["冷蔵庫を開けっぱなしにしていた。"],
  },
  importance: "normal",
}
```

## 10. 機能仕様

### 10.1 ごはん

- 食べ物を選んで与える。食べ物は **食材**（そのまま）と **料理**（食材の組み合わせで解放）の 2 種類。
- 各食べ物は味タグ・満腹度・散らかし度を持つ。
- 反応（大好き / ふつう / 苦手）は好みの好感度で決まり、あげるほど好みが強化される。
- 苦手なものも何度もあげると慣れることがある（好み形成の面白さ）。
- 食べ物の入手: 初期所持 + 散歩の拾い物 + 1 日 1 回の「おすそわけ」（補充）。**通貨は無し**（D8）。

### 10.2 遊ぶ（ミニゲーム）

- 1 プレイ 3〜10 秒。ワンタップ〜スワイプで完結するもの。ミニゲームはクライアント側で動かし、**結果だけ**をサーバーに送る。
- 初期案（3 種）:
  1. **キャッチ**: 落ちてくるおやつを左右移動でキャッチ
  2. **かくれんぼ**: 家具の後ろに隠れたペットをタップで当てる
  3. **リズムタップ**: ペットの鼻歌に合わせて 3 回タップ
- 結果に関わらず退屈↓・活発さ↑。成功すると機嫌↑。
- ペットの性格で得意なゲームが変わる（例: のんびり屋はかくれんぼで寝てしまう）。

### 10.3 掃除

- 散らかり度が上がると、部屋にゴミ・食べこぼし・おもちゃが描画される。
- ゴミをタップ（またはスワイプ）で片付ける。まとめて片付ける「掃除機」ボタンも用意。
- 片付けると きれい好き↑ 方向へ少し影響。放置するとずぼら↑、収集癖の趣味が生まれやすくなる。
- 散らかった部屋の中から、たまに**アイテムが見つかる**（掃除のご褒美）。

### 10.4 睡眠

- 現実時刻に連動して自動で寝起きする（4.5 参照）。
- 眠気が高いと昼間でも昼寝する。
- ユーザー操作: 「電気を消す」で寝かしつけ（寝つきが良くなる）、寝ている間にタップすると起きる。
- 就寝中は画面が暗くなり（夜パレット）、寝言（会話）が出ることがある。

### 10.5 会話

- 部屋のペットの上に吹き出しで短いコメント（〜20 文字程度）を表示。
- ペットをタップすると話す。放置中は一定間隔で独り言。
- コメントの素材:
  - 現在の欲求（「おなかすいた…」）
  - 直近のタイムライン（「さっきコイン拾ったよ」）
  - 好み・趣味（「トマトはもういい」）
  - 時間帯・曜日・季節（「月曜日だね」）
  - 留守の長さ（「おかえり、長かったね」）
  - 親の世代の思い出（「おやの形見のコップ、大事にしてる」）
- 性格・ライフステージで語尾や言い回しを変える（ベビーは片言、シニアは昔話）。
- すべてテンプレートで生成（LLM 連携は将来の拡張候補）。

### 10.6 散歩

- 最後の操作から **一定時間（例: 2 時間）** 以上経つと、ペットが自発的に散歩に出ることがある。
- 散歩中の部屋は空っぽで、「おでかけ中」の書き置きが置かれている。
- 30 分〜3 時間で帰宅し、**アイテムを拾ってくる**。
- 拾うアイテムは 好奇心・趣味・時間帯・季節 で抽選。レア度あり。
- 散歩先での出来事もタイムラインに記録（「公園で知らない犬と目が合った」）。
- シニア期は散歩の頻度が下がり、近場で済ませる。

### 10.7 着せ替え

- スロット: 帽子 / 服 / アクセサリ（顔まわり）/ 手持ち の 4 つ。
- Canvas 上でスプライトを重ねて描画（5.2 参照）。
- 入手: 拾い物、図鑑の達成報酬、成長の節目。
- ペットの好みがある（嫌いな服を着せると機嫌↓、脱ぎ捨てて部屋が散らかることも）。

### 10.8 部屋

- 変更できる要素: 壁紙 / 床 / 家具（配置スロット制、6〜8 か所）
- 家具はペットの行動候補を増やす（本棚 → 読書、植木鉢 → 水やり、窓 → 外を見る、冷蔵庫 → 勝手に開ける）。
- 家具配置は「スロット制」（自由配置より実装が簡単でスマホで操作しやすい）。
- 部屋は世代をまたいで引き継がれる。

### 10.9 図鑑

| カテゴリ | 登録条件 |
|---|---|
| 種族 | その姿に進化したことがある（どの世代でも可） |
| 食べ物 | 一度でも食べた（好みの反応も記録） |
| アイテム | 拾った・入手した |
| 趣味 | 獲得したことがある |
| イベント | 珍しいイベントを見た（日記の名場面集） |

- 未登録はシルエットとヒントを表示。
- 達成率に応じて着せ替えや家具がもらえる。
- 旅立ったペットの一覧は「思い出」（7.5）として図鑑と並べて表示。

### 10.10 写真

- 部屋の画面で「📷」ボタン → クライアントで Canvas を PNG にしてサーバーへアップロード。
- サーバーは `data/photos/` に画像を保存し、DB にメタデータ（撮影時刻・ペット・世代・キャプション）を保存。
- キャプションは直近の日記 1 行から自動で付ける（あとで編集可）。
- アルバム画面で一覧表示。スマホで撮った写真も PC から見られる。端末への保存はダウンロード / Web Share API。
- ペットが自分で「自撮り」する低確率イベントもあり（サーバー側で描画するのは重いので、「次に開いたときにクライアントで撮影して保存」する）。

### 11.3 実装メモ（P6 演出）

|---|---|
| 節目の記録 | sim が段階の変わり目で `state.ceremonies` に積む（孵化・進化〔こども／ティーン／おとな〕・シニア。最期の日は旅立ちの演出があるので入れない）。長く留守にしても新しい 4 つまで |

| 孵化 | たまごがだんだん速くゆれる → ひびがのびる → 白く光って割れる → からが左右に分かれ、赤ちゃんが喜ぶ。「たまごが かえった！」 |

## 12. API（概略）

すべて JSON。リクエストを受けたらまずキャッチアップ計算（4.1）を行ってから処理する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/state` | 現在のペット・部屋・持ち物・未読件数（ホーム画面用） |
| GET | `/api/timeline?generation=&before=&limit=` | 日記（ページング） |
| POST | `/api/timeline/read` | 指定時刻までを既読にする |
| POST | `/api/actions` | 操作を送る（下記） |
| GET | `/api/collection` | 図鑑 |
| GET | `/api/memorial` | 歴代ペット一覧・詳細 |
| GET / POST | `/api/photos` | 写真一覧 / アップロード（multipart） |
| GET | `/api/photos/:id.png` | 写真の画像 |
| GET | `/api/export` | バックアップ（DB ファイルをダウンロード） |
| POST | `/api/debug/advance` | 開発用: 時間を早送り（開発モードのみ） |

`/api/actions` の例:

```jsonc
{ "type": "feed",      "foodId": "tomato" }
{ "type": "clean",     "litterIds": ["l_12", "l_13"] }
{ "type": "play",      "game": "catch", "score": 7 }
{ "type": "lights",    "on": false }
{ "type": "wake" }
{ "type": "equip",     "slot": "hat", "itemId": "straw_hat" }
{ "type": "place",     "slot": "slot_3", "furnitureId": "bookshelf" }
{ "type": "talk" }     // ペットをタップ → コメントを返す
```

- レスポンスは更新後の状態 + そのとき起きた反応（「大好き！」など）+ 新しい日記エントリ。
- 各アクションに `clientActionId` を付けて、同じ操作が二重に送られても 1 回だけ処理されるようにする（スマホで連打・再送した場合の対策）。

### 13.2 ペット状態（`state_json`）

```ts
interface PetState {
  stage: "egg" | "baby" | "child" | "teen" | "adult" | "senior" | "final_day" | "departed";
  speciesId: string;
  needs: { hunger: number; sleepiness: number; boredom: number; loneliness: number };
  personality: {
    energy: number; tidiness: number; curiosity: number;
    attachment: number; appetite: number; chronotype: number;
  };
  foodPrefs: Record<string, number>;   // 味タグ → 好感度
  hobbies: string[];
  activity: { type: string; since: number; location?: string };
  equipped: { hat?: string; clothes?: string; accessory?: string; hand?: string };
  lifespanModifier: number;            // 世話による寿命の前後（日）
  stats: Record<string, number>;       // 一生の集計（冷蔵庫を開けた回数など。最後のひとこと・思い出用）
  keepsakeItemId?: string;             // 形見候補（一番大事にしているもの）
}
```

- 状態の構造が変わっても対応できるよう、`schema_version` を見て起動時にマイグレーションする。
- バックアップは SQLite ファイルと `photos/` フォルダをコピーするだけでよい。
