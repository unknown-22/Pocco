# バージョンと更新履歴

## 基準

- PR #10 を取り込んだ main（`6e2dc42`）を **0.1.0** の基準版とする。これより前の版番号・公開日は遡って作らない。
- 更新履歴の表示を追加した版は **0.1.1**。今回はバージョン管理の導入として、この番号から始める。
- 今後は `0.MINOR.PATCH`。機能追加・大きな UI 変更は MINOR、小さな改善・修正・文言・見た目・バランス調整は PATCH を上げる。
- 実機確認を終えて安定版と判断したら `1.0.0` にする。
- アプリの版と SQLite のスキーマ番号は独立。アプリの更新だけでは DB のマイグレーション番号を変えない。

## 更新手順

履歴の正は `apps/web/src/changelog.json`。画面の版表示も先頭の `version` を参照する。別の履歴データや外部 API は使わない。

1. JSON の先頭に新しい版を追加する。`version`、`date`、`title`、`items` を持ち、`items` は `category`（追加・改善・修正）と `text` の組にする。
2. `date` は実際の公開日を `YYYY-MM-DD` で記録する。公開前など未確定なら `null` にし、公開時に確定する。基準版で日付が分からない場合も `null` のままにする。画面では「公開日未記録」と表示する。
3. ルートと全 workspace の `package.json`、`package-lock.json` の版を同じ値にする。パッケージは非公開で、アプリ全体として同じ版で管理する。
4. `npm test` と `npm run build` を実行する。JSON の形・並び順・日付・版の整合性はテストで確認する。
5. 設定 → 更新履歴の表示、過去の版の開閉、シート内スクロール、閉じる・背景タップ・再表示、ライト／ダークとスマホ幅で確認する。公開前に日付を更新した場合も再度テストする。

履歴はビルドに同梱され、新しい版から表示する。最新版は展開し、過去の版は折りたたむ。自動ポップアップや既読管理はしない。
